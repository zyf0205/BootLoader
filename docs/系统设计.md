# 系统设计

## 硬件配置

| 资源 | 配置 |
|---|---|
| MCU | STM32F411CEU6，512 KB Flash，128 KB SRAM |
| HSE | 12 MHz 晶振 |
| SYSCLK/HCLK | 96 MHz |
| PCLK1 | 48 MHz |
| PCLK2 | 96 MHz |
| USART1 | PA9 TX、PA10 RX、115200-8-N-1 |
| LED | PA1，低电平点亮 |
| KEY | PC13，低电平按下，内部上拉 |

HSE 经 PLL 配置为 `M=12, N=192, P=2`，得到 96 MHz。HSE 启动失败时使用 16 MHz HSI 和 `M=16` 维持相同系统频率。

## Flash 分区

| 区域 | 地址范围 | 大小 | STM32F4 扇区 | 用途 |
|---|---|---:|---|---|
| Bootloader | `0x08000000-0x08003FFF` | 16 KB | Sector 0 | 启动和升级程序 |
| APP | `0x08004000-0x0803FFFF` | 240 KB | Sector 1-5 | 用户固件 |
| Metadata | `0x08040000-0x0805FFFF` | 128 KB | Sector 6 | 固件元数据，使用前 16 B |
| Reserved | `0x08060000-0x0807FFFF` | 128 KB | Sector 7 | 预留 |

元数据包含魔数、固件大小、CRC32、版本号和保留字段。APP 有效性检查要求：元数据魔数及大小有效、初始 MSP 位于 SRAM、Reset 向量位于 APP 分区且 Thumb 位为 1，并且全固件 CRC32 与元数据一致。

## 启动决策

Bootloader 初始化 SysTick、LED、按键、Flash、USART 和升级器后，按固定优先级作出启动决策：

1. APP 通过两个备份寄存器写入魔数及反码并软复位时，消费一次性请求并进入升级模式。
2. 上电或复位时 PC13 连续保持按下约 100 ms，进入升级模式。
3. APP 元数据、向量表或固件 CRC32 任一校验失败时，进入恢复升级模式。
4. APP 完整有效且没有升级请求时，立即跳转 APP，不发送 YMODEM 邀请字符。
5. 以上决策之前，若检测到连续 3 次 HardFault 复位（RTC BKP4R 计数，
   跨复位保持），则不再自动跳 APP，停留在升级模式等待修复，
   避免 Fault-复位-Fault 无限循环；正常启动或进入升级模式时清零计数。

启动策略由独立的纯逻辑模块实现，可在主机环境按决策表单元测试。Bootloader 等待模式慢闪 LED，便于与 APP 区分。演示 APP 接入按键：长按 USER 键（PC13）约 1.5 s 即调用 `Boot_RequestBootloader()` 软件重入升级模式（短按不动作，长按期间 LED 快闪提示）；该 API 同样供业务固件的串口命令等入口调用。

APP 有效性检查包括元数据魔数与长度、初始 MSP、Reset 向量以及全固件 CRC32。开始擦除 APP 前先使旧元数据失效；升级完成后先写入大小、CRC32 和版本等内容，最后写入 magic 作为提交点。升级中途掉电时，下一次启动不会误运行半写固件。

## 升级流程

YMODEM 协议层与硬件无关，逐字节接收串口数据并通过回调交给升级器。喂字节与 1ms 节拍均在主循环中调用（中断只累积节拍计数），状态机单上下文串行访问，不存在中断/主循环竞态：

1. 周期发送 `C` 请求 CRC16 模式。
2. 接收序号 0 的 128 B 文件头，解析文件名和十进制文件大小（超过 9
   位的数字串与 63 字节以上未终止的文件名均整包拒绝）。此时旧元数据
   尚未失效，执行防降级检查：APP 完好时拒绝低于已装版本的固件；
   recovery 态与文件名无 `vX.Y` 版本号时放行，保证旧版本可救砖。
3. 回复 `ACK`，擦除 APP Sector 1-5，擦除完成后发送第二个 `C`。
4. 接收 128 B SOH 或 1 KB STX 数据包，校验序号、反码和 CRC16。
5. 按文件真实大小写入 Flash，末包填充字节不写入，并逐包回读验证后回复 `ACK`。
6. 按 `EOT -> NAK -> EOT -> ACK + C` 完成文件结束握手。
7. 接收空文件头并回复 `ACK`。此后会话结束，杂散字节一律忽略。
8. 计算 APP CRC32，以 magic 最后写入的方式提交元数据，等待 1 秒后受控复位。
9. 复位后跳过升级按键检测一次，重新校验元数据、向量表和 CRC32，再从干净的硬件状态启动 APP。

CRC 错误、包序号错误和超时会请求重传；重复数据包只重发 ACK，不重复写 Flash。数据序号按 8-bit 回绕比较（255 之后回到 0），SOH 传输超过 255 包不会失败。包中途超过 1 s 无后续字节视为半包滞留，丢弃后要求重传；校验失败的包若原始字节流含 `CAN CAN`，判定为发送端取消并立即中止，不再重传超时。连续错误达到上限后发送 `CAN CAN` 中止并重新等待。接收端另检测 RX 环形缓冲溢出（DMA 覆盖未读数据，如发送端在擦除期间不等 `C` 硬冲），溢出后丢弃缓冲并重启接收会话。

## APP 跳转

跳转前先校验 APP 向量表并等待 USART 日志发送完成，然后关闭全局中断和 USART、将用过的 GPIO 端口整端口复位为浮空输入（`RCC_DeInit` 不复位 GPIO 配置）、停止 SysTick、清除 NVIC 使能及挂起状态、复位 RCC 并显式清零 AHB1/APB1/APB2 外设时钟使能位（`RCC_DeInit` 同样不清这些位）。最后设置 `VTOR` 和 MSP，恢复全局中断并调用 APP Reset_Handler。APP 的 SystemInit 会重新建立 12 MHz HSE 到 96 MHz 的时钟树。
