# 系统设计

## 硬件配置

| 资源 | 配置 |
|---|---|
| MCU | STM32F411CEU6，512 KB Flash，128 KB SRAM |
| HSE | 12 MHz 晶振 |
| SYSCLK/HCLK | 96 MHz |
| PCLK1 | 48 MHz |
| PCLK2 | 96 MHz |
| USART1 | PA9 TX、PA10 RX、115200-8-N-1 |
| LED | PA1，低电平点亮 |
| KEY | PC13，低电平按下，内部上拉 |

HSE 经 PLL 配置为 `M=12, N=192, P=2`，得到 96 MHz。HSE 启动失败时使用 16 MHz HSI 和 `M=16` 维持相同系统频率。

## Flash 分区

| 区域 | 地址范围 | 大小 | STM32F4 扇区 | 用途 |
|---|---|---:|---|---|
| Bootloader | `0x08000000-0x08003FFF` | 16 KB | Sector 0 | 启动和升级程序 |
| APP | `0x08004000-0x0803FFFF` | 240 KB | Sector 1-5 | 用户固件 |
| Metadata | `0x08040000-0x0805FFFF` | 128 KB | Sector 6 | 固件元数据，使用前 16 B |
| Reserved | `0x08060000-0x0807FFFF` | 128 KB | Sector 7 | 预留 |

元数据包含魔数、固件大小、CRC32、版本号和保留字段。APP 有效性检查要求：元数据魔数及大小有效、初始 MSP 位于 SRAM、Reset 向量位于 APP 分区且 Thumb 位为 1。

## 启动决策

Bootloader 初始化 SysTick、LED、按键、Flash、USART 和升级器后判断启动原因：

1. APP 通过备份寄存器写入魔数并软复位时，进入无限等待升级模式。
2. 复位时 PC13 保持按下约 50 ms，进入无限等待升级模式。
3. 没有有效 APP 时，进入无限等待升级模式。
4. 正常启动且 APP 有效时，发送 YMODEM 邀请字符 `C` 并等待 5 秒；没有收到有效文件头则跳转 APP。

APP 演示程序每 1.5 秒翻转 LED，完整亮灭周期约 3 秒；Bootloader 等待模式每 500 ms 翻转 LED，完整周期约 1 秒，便于区分。APP 中长按 PC13 约 2 秒会写入重入魔数并复位。

## 升级流程

YMODEM 协议层与硬件无关，逐字节接收串口数据并通过回调交给升级器：

1. 周期发送 `C` 请求 CRC16 模式。
2. 接收序号 0 的 128 B 文件头，解析文件名和十进制文件大小。
3. 回复 `ACK`，擦除 APP Sector 1-5，擦除完成后发送第二个 `C`。
4. 接收 128 B SOH 或 1 KB STX 数据包，校验序号、反码和 CRC16。
5. 按文件真实大小写入 Flash，末包填充字节不写入，并逐包回读验证后回复 `ACK`。
6. 按 `EOT -> NAK -> EOT -> ACK + C` 完成文件结束握手。
7. 接收空文件头并回复 `ACK`；最终 ACK 丢失时仍会应答重发的空文件头。
8. 计算 APP CRC32、保存元数据，等待 1 秒后跳转 APP。

CRC 错误、包序号错误和超时会请求重传；重复数据包只重发 ACK，不重复写 Flash。连续错误达到上限后发送 `CAN CAN` 中止并重新等待。

## APP 跳转

跳转前先校验 APP 向量表并等待 USART 日志发送完成，然后关闭全局中断和 USART、停止 SysTick、清除 NVIC 使能及挂起状态、复位 RCC。最后设置 `VTOR` 和 MSP，恢复全局中断并调用 APP Reset_Handler。APP 的 SystemInit 会重新建立 12 MHz HSE 到 96 MHz 的时钟树。
