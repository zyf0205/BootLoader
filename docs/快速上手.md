# 快速上手

从零开始,一次跑通整个 Bootloader 升级流程。全程约 30 分钟。

## 1. 准备清单

### 硬件

| 物品 | 说明 |
|------|------|
| STM32F411CEU6 开发板 (Black Pill) | 本项目目标板 |
| ST-Link 调试器 | 首次烧录 Bootloader 用 |
| USB 转串口模块 | 升级固件用 (或开发板自带) |

### 软件 (Windows)

| 软件 | 用途 | 下载 |
|------|------|------|
| VSCode | 编辑器 | code.visualstudio.com |
| EIDE 插件 | 工程管理/编译/烧录 | VSCode 扩展市场搜 `cl.eide` |
| Keil MDK v5.32+ | 提供 AC5 编译器 | keil.com (EIDE 会自动找到) |
| Tera Term | 串口终端 + YMODEM 发送 | github.com/TeraTermProject |

## 2. 编译 Bootloader

1. 双击打开根目录的 `BootLoader.code-workspace`(VSCode)
2. 左侧 EIDE 面板找到 **bootloader** 工程,右键 **Build** 构建
3. 构建成功后产物在 `bootloader/build/bootloader/Bootloader.bin`(约 11KB,必须小于 16KB)

> 首次构建若提示找不到编译器:在 EIDE 工程属性里确认工具链为 **AC5**,编译路径指向
> Keil 的 `ARM\ARMCC` 目录。

## 3. 烧录 Bootloader (只需一次)

1. ST-Link 连接开发板(SWD 四线 + 3.3V + GND)
2. EIDE 面板 bootloader 工程 → **Flash**(或右键 Upload)
3. 烧录地址已配置为 `0x08000000`,无需手动设置

## 4. 编译 APP 固件

1. EIDE 面板 **app** 工程 → **Build**
2. 产物:`app/build/app/App.bin`(约 2KB)
3. **这一步只编译不烧录** —— APP 要由 Bootloader 通过串口写入

> 为什么要走串口而不直接用 ST-Link 烧 APP?
> 因为 Bootloader 判断"APP 是否有效"依赖元数据区(Sector 6)的记录,
> 只有串口升级流程才会写入元数据。ST-Link 直接烧 APP 后 Bootloader 仍会
> 认为"无有效 APP"而停在升级模式—— 属预期行为,再做一次串口升级即可。

## 5. 连接串口

| 开发板 | USB 转串口 |
|--------|-----------|
| PA9 (USART1_TX) | RXD |
| PA10 (USART1_RX) | TXD |
| GND | GND |

参数:**115200 / 8 / N / 1**,无流控。

## 6. 第一次升级 (安装 APP)

1. 打开 Tera Term,选 `Serial`,选择 USB 转串口对应的 COM 口,波特率 115200
2. 给开发板上电或按复位键,串口应打印:

```
============================================
  STM32F411 Bootloader v3.0.0
  Protocol : YMODEM (CRC16, 1K packet)
  Build    : ...
============================================

No valid APP, enter update mode.
```

   (首次烧录没有 APP,自动进入升级模式,LED 慢闪表示等待)

3. Tera Term 菜单:`File → Transfer → YMODEM → Send...`
4. 文件类型选 `*.*`,选择 `app/build/app/App.bin`,确认 **1k 选项勾选**,点 Open
5. 观察串口输出,正常流程:

```
File   : App.bin
Size   : 1888 bytes
Erasing APP region...OK

Receiving done.
Verifying CRC32...OK (0xXXXXXXXX)
Saving metadata...OK

Update success! Jumping to APP in 1 s...
```

6. 约 1 秒后跳转 APP,板上 LED 开始闪烁 —— **升级成功!**

## 7. 验证 APP 的"长按回 Bootloader"

APP 运行期间(对应引脚 **PC13**):

1. **按住按键 2 秒以上**
2. 松开后设备复位,串口打印:

```
Update requested by APP.
```

3. 进入升级模式 —— 随时可以再次升级

## 8. 日常升级流程 (以后每次)

以后升级固件,只要:

1. 修改代码 → EIDE 构建 `app` 工程得到新 App.bin
2. 串口接好 → Tera Term 打开
3. 让设备进入升级模式(三选一):
   - **APP 里长按按键 2 秒**(最方便)
   - **按住按键再按复位键**(进不去 APP 时)
   - 复位后在 5 秒窗口内直接发送 YMODEM(APP 有效时)
4. YMODEM 发送新固件 → 自动完成升级并跳转

> 升级过程中途失败(拔线、文件错误等)不用担心:
> 设备会自动回到"等待状态",重新发送即可;Flash 里的旧 APP 已被擦除,
> 但在新固件写完前不会跳转,不会出现半死机状态。

## 9. 固件版本号约定 (可选)

固件文件名含 `vX.Y` 时,版本号会自动解析并存入元数据:

```
app.bin        ->  版本 0x0000 (未指定)
app_v1.0.bin   ->  版本 0x0100
app_v2.15.bin  ->  版本 0x020F
```
