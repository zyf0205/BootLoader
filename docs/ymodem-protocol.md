# YMODEM 协议说明

## 1. 协议概述

YMODEM 是 XMODEM 的批处理增强版, 支持 **文件名 + 文件大小** 传输, 是串口 Bootloader 的经典协议。本工程实现**接收端**(Bootloader 侧), 发送端使用任意支持 YMODEM 的终端软件。

## 2. 帧格式

### 2.1 文件头包 (固定 128 字节数据段)

```
[SOH=0x01][SEQ=0x00][~SEQ=0xFF][ 文件名\0大小\0... 共128B ][CRC16_H][CRC16_L]
```

### 2.2 数据包 (1024 或 128 字节数据段)

```
[STX=0x02|SOH=0x01][SEQ][~SEQ][ DATA ][CRC16_H][CRC16_L]
```

- SEQ 从 1 开始递增, 溢出回绕; 恒有 `SEQ + ~SEQ = 0xFF`
- 末包不足 1024/128 字节时, 发送端用 `0x1A` 填充对齐
- 本工程接收端同时支持 STX (1K) 和 SOH (128) 数据包

### 2.3 CRC16 (XMODEM 变体)

- 多项式 `0x1021`, 初始值 `0x0000`, 无反射
- 校验范围: 数据段 (不含包头和 CRC)
- 检查值: `"123456789"` -> `0x31C3`

## 3. 交互时序

```
接收端(Bootloader)                    发送端(Tera Term)
      |                                       |
      |------ 'C' (0x43, 请求CRC模式) -------->|
      |<------ 文件头包 (SEQ=0) ---------------|
      |------ ACK --------------------------->|
      |<------ 数据包 SEQ=1 ------------------|
      |------ ACK --------------------------->|
      |<------ 数据包 SEQ=2 ------------------|
      |------ ACK --------------------------->|
      |           ... 直至所有数据 ...          |
      |<------ EOT ---------------------------|
      |------ NAK --------------------------->|   (首次 EOT 必须 NAK)
      |<------ EOT ---------------------------|
      |------ ACK --------------------------->|
      |<------ 空文件头 (文件名为空) ----------|
      |------ ACK --------------------------->|   (传输完成)
```

## 4. 差错恢复

| 场景 | 接收端动作 |
|------|-----------|
| 数据包 CRC/序号错误 | NAK, 发送端重传该包 |
| 重复包 (ACK 丢失) | 再次 ACK, 数据不重复写入 |
| 等待数据包超时 (3s) | 重发上次响应, 连续 5 次超时则 CAN CAN 中止 |
| 文件过大 / Flash 写入失败 | CAN CAN 中止 |
| 发送端中止 (收到 CAN) | 响应 CAN CAN, 结束会话 |

## 5. 本工程的实现细节

### 5.1 状态机 (ymodem.c)

```
IDLE -> WAIT_HEADER -> RX_DATA -> WAIT_EOT -> DONE
         |              |    |
         +--> 'C' 周期重发(1s)  +--> 首次EOT: NAK
                               +--> 二次EOT: ACK -> 等待空包
         ABORTED (CAN/CAN 后进入)
```

- 逐字节喂入 (`ymodem_feed`), 无阻塞, 主循环轮询驱动
- 1ms tick 处理超时 (`ymodem_tick`)
- CAN 检测仅在包间隙生效 (数据字节可能为 0x18)

### 5.2 与 Bootloader 的集成 (updater.c)

- `on_header`: 解析文件名/大小/版本, 校验 0 < size <= 240KB, 擦除 APP 区
- `on_data`: 按文件大小截断写入 (忽略末包填充), Flash 写后回读验证
- `on_complete`: 大小核对 -> 硬件 CRC32 全量校验 -> 写入元数据 -> 跳转 APP
- `on_abort`: 打印原因, 自动重启接收 (发 'C')

### 5.3 版本号约定

固件文件名包含 `vX.Y` 时自动解析存入元数据, 例如:

```
app_v1.2.bin  ->  版本 0x0102
app.bin       ->  版本 0x0000 (未指定)
```
