# 常见问题

## 串口相关

### Q1: 上电后串口什么输出都没有?

依次检查:

1. **串口线接反**:PA9(TX)必须接 USB 转串口的 RXD,PA10(RX)接 TXD
2. **波特率**:必须 115200(不是 9600)
3. **Tera Term 串口选对**:Windows 设备管理器确认 COM 号
4. **供电**:串口模块的 GND 与开发板共地
5. **Bootloader 真的烧进去了吗**:用 ST-Link 重新烧录一次,勾选复位运行
6. 换串口调试助手(如串口猎人/XCOM)试一下,排除 Tera Term 设置问题

### Q2: 输出是乱码?

- 波特率不对(最常见)
- 串口模块质量差,换一个
- 检查系统时钟是否被改过(默认 HSI 96MHz,见 `libraries/cmsis/system/system_stm32f4xx.h`)

### Q3: 复位后总是显示 "No valid APP"?

**完全正常**的一种情况:你还没用 YMODEM 升级过,或者上次升级中途失败。见 [快速上手](快速上手.md) 第 4 节说明 —— 必须走一次串口升级才会写入元数据,APP 才被认可。

如果**已经成功升级过**还这样:

- 升级时看到 `Saving metadata...OK` 了吗?没看到说明元数据没写成功
- 检查 Flash 是否写保护(读保护 RDP 等级不为 0 时会写失败)

## 升级相关

### Q4: Tera Term 发送后卡在等待,设备一直发 'C'?

- 确认设备确实在升级模式(LED 慢闪,串口每秒有输出)
- Tera Term 发送对话框里 **1k 选项必须勾选**(默认勾选,别取消)
- 试试先按住 KEY 复位进入升级模式,再点发送

### Q5: 升级中途失败/断线了怎么办?

什么都不用做 —— 设备会自动回到等待状态(LED 慢闪,重新发 'C')。
重新执行 YMODEM 发送即可。旧 APP 已被擦除,但新固件没写完前不会跳转,设备不会变砖。

### Q6: 升级成功了但 APP 不运行?

1. 串口日志是否看到 `Update success!`?没有则升级实际未完成
2. LED 是否常亮 1 秒后熄灭再闪烁?若一直常亮,卡在跳转——检查 APP 工程的链接地址是否为 0x08004000(`app/.eide/eide.yml` 的 `ro-base`)
3. 用 ST-Link 重新烧录 Bootloader,确认 Bootloader 本身是好的

### Q7: 固件超过 240KB 怎么办?

设计上限就是 240KB(APP 分区大小)。超过时会收到:

```
Error: file size xxx out of range (max 245760).
```

需要:缩小固件(开启 `-O2` 优化、精简库)、或调整 Flash 分区(见 [架构详解](架构详解.md) 第 5 节,注意要同步改两个工程的链接配置和 `boot_api.h`)。

### Q8: 发送错误码 NACK 怎么办?

观察 Tera Term 提示和串口日志:

| 日志关键词 | 含义 | 处理 |
|-----------|------|------|
| `size out of range` | 文件太大 | 见 Q7 |
| `flash write failed` | Flash 写失败 | 检查 RDP 读保护等级 |
| `address overflow` | 写入越界 | 文件大小与分区不符 |
| `size mismatch` | 收到的数据量与文件头不符 | 重发一次 |
| `Aborted: ...` | 各种中止 | 看具体原因,一般重发即可 |

## 按键与 LED

### Q9: LED 不亮/不闪?

- 检查 `modules/board/board.h` 中 `LED_PORT/LED_PIN` 是否与你的板子一致
- 本项目默认 PA1 低电平点亮,有些板子板载 LED 是 PC13(与按键冲突,本项目按键占用 PC13)
- 改引脚后两个工程各有一份 board.h,记得都改

### Q10: 按键长按/复位按键没反应?

- 默认按键是 **PC13**(低电平按下),不是所有板子的按键都在 PC13
- 开机按住 50ms 即判定"强制进 BL";APP 里需按住 **2 秒**
- 改按键引脚:`modules/board/board.h` 的 `KEY_PORT/KEY_PIN`

### Q11: APP 里长按回不了 Bootloader?

1. 确认按的是 PC13,按住时间超过 2 秒
2. 串口复位后应打印 `Update requested by APP.` —— 打印了说明成功
3. 没打印:检查 APP 代码里 `Boot_RequestBootloader()` 是否被调用
4. 备份寄存器依赖软复位保持:APP 若执行了**断电重启**(拔电源)而不是软复位,魔数会丢 —— 长按触发的是 `NVIC_SystemReset()` 软复位,不会有此问题

## 开发与工具

### Q12: EIDE 构建报错找不到编译器?

- 确认安装了 Keil MDK v5.32 及以上(AC5 编译器)
- EIDE 工程属性 → 工具链选择 **AC5**;若路径没自动识别,手动指向 Keil 安装目录 `ARM\ARMCC`
- 构建报 `__use_two_region_memory` 未定义:EIDE 工程设置里勾选 **use microLIB**(本项目已配置)

### Q13: 想验证代码但不想开 VSCode?

```bash
# WSL 下调用 Windows Keil AC5 全量编译验证 (零错误零警告 + 16KB 体积检查)
bash tools/build_check.sh

# YMODEM 协议单元测试 (改过协议层必跑)
cd tests/ymodem && make test
```

### Q14: 改了代码后 Bootloader 体积超 16KB 了?

- 当前占用约 11KB,余量约 5KB
- 急救手段:EIDE 工程属性里把优化等级从 `-O0` 提到 `-O2`(可省 2-3KB)
- 长期手段:精简 printf 使用(microlib printf 约 2KB)、删减未用模块
- 彻底方案:调整分区,把 Bootloader 扩到 32KB(Sector 0+1,APP 相应后移,需同步改 `boot_api.h`、两个 eide.yml、`flash.c` 扇区表)

## 硬件相关

### Q15: 板子上没有 25MHz 晶振怎么办?

本项目默认用 **HSI 内部时钟 16MHz → PLL 96MHz**,不依赖外部晶振。
若你的板子有 25MHz 晶振想用 HSE,改 `libraries/cmsis/system/system_stm32f4xx.h`:

```c
#define CLOCK_USE_HSE   1
```

两个工程各有一份,需要同步修改。

### Q16: 可以用 STM32F401/F407 吗?

可以移植,但本项目是按 F411 配置的,至少需要改:

1. `libraries/stdperiph/inc/stm32f4xx.h` 里的芯片宏定义(STLink 烧录时 EIDE 也会用到)
2. EIDE 工程定义 `STM32F411xE` → 对应芯片宏
3. `flash.c` 扇区表(F401 只有 256KB Flash,分区完全不同)
4. 时钟配置(F401 上限 84MHz)
