# 开发与构建

## 推荐环境

日常开发可使用 Windows 上的 Keil MDK，也可使用 VSCode 和 EIDE 插件。两种方式均使用 Keil MDK 自带的 ARM Compiler 5。仓库位于 Windows 磁盘，WSL 中的 Agent 通过 `/mnt/<盘符>/...` 访问源码，并直接调用 Windows 工具链验证。

本机已验证环境：

- Keil MDK 5.32
- ARM Compiler 5.06 update 7
- 工具链目录 `D:/Keil_v5/ARM/ARMCC/bin`
- Keil 工程为 `bootloader/bootloader.uvprojx` 和 `app/app.uvprojx`
- EIDE 工程配置分别位于 `bootloader/.eide/` 和 `app/.eide/`

## Keil 工程

两个子目录都是可单独打开、编译和烧录的工程：

| Keil 工程 | Target | 链接地址 | BIN |
|---|---|---:|---|
| `bootloader/bootloader.uvprojx` | `bootloader` | `0x08000000` | `bootloader/build/bootloader/Bootloader.bin` |
| `app/app.uvprojx` | `app` | `0x08004000` | `app/build/app/App.bin` |

Keil 工程已配置 AC5、microlib、完整源码组和构建后 `fromelf --bin`。可在 uVision 中分别打开，也可从 WSL 非交互验证：

```bash
/mnt/d/Keil_v5/UV4/UV4.exe -b app/app.uvprojx -t app
/mnt/d/Keil_v5/UV4/UV4.exe -b bootloader/bootloader.uvprojx -t bootloader
```

## EIDE 日常流程

用 VSCode 打开根目录的 `BootLoader.code-workspace`。工作区同时加载两个自包含工程：

| EIDE 目标 | 链接地址 | ROM 大小 | 构建后 BIN |
|---|---:|---:|---|
| `bootloader` | `0x08000000` | `0x4000` | `bootloader/build/bootloader/Bootloader.bin` |
| `app` | `0x08004000` | `0x3C000` | `app/build/app/App.bin` |

两个目标均使用 Cortex-M4 单精度 FPU、C99、microlib 和 AC5。EIDE 配置已启用 BIN 输出，构建完成后会在各目标输出目录生成 AXF 和 BIN；实际文件名以 EIDE 构建日志为准。

Bootloader 首次烧录到 `0x08000000`；APP 可由 EIDE/ST-Link 直接烧录到 `0x08004000`，也可将 `App.bin` 通过 YMODEM 发送给 Bootloader。不要把 HEX 文件当作升级文件发送。

## WSL Agent 验证

仓库提供独立于 VSCode UI 的验证入口：

```bash
bash tools/build_check.sh
```

脚本使用相对源码和输出路径调用 Windows 下的 `armcc.exe`、`armasm.exe`、`armlink.exe` 和 `fromelf.exe`，完成两个目标的全量编译、链接、BIN 生成及 Bootloader 16 KB 限制检查。输出位于根目录 `build/check/`，不会提交。

Windows 可执行文件能够从 WSL 启动，但参数中的 `/mnt/...` 路径通常不能被 ARMCC 正确识别。因此脚本必须在仓库根目录运行，并向工具链传递相对路径。

协议状态机还可使用 Linux GCC 独立测试：

```bash
make -C tests/ymodem test
```

## 配置同步原则

以下内容改变时，必须同时修改 Keil `.uvprojx`、EIDE 配置和 `tools/build_check.sh`：

- 新增或删除参与构建的源文件
- 预处理宏和 include 路径
- CPU/FPU、microlib 或编译模式
- Flash/RAM 链接地址和大小

时钟和板级引脚由两个工程各自的 `libraries/cmsis/system/`、`libraries/stdperiph/inc/stm32f4xx.h` 与 `modules/board/board.h` 定义。两个工程独立，公共契约变更要同步修改。

## AC5 注意事项

- `--c99` 下异常入口使用 `__asm void` 函数形式，不使用 `__asm {}`。
- microlib 启动文件汇编需要 `--pd "__MICROLIB SETA 1"`。
- microlib 的 `printf` 重定向位于 Bootloader USART 驱动中。
- F411 的 PWR VOS 使用 `PWR_CR_VOS_0`。
- 提交 `.uvprojx`、`.eide/` 和工程实际依赖的 CMSIS/库文件；不提交 `build/`、对象文件、AXF、MAP、BIN 或 IDE 用户状态。
