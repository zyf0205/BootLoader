# 架构设计

## 1. 分层视图

```
+--------------------------------------------------------------+
|  Bootloader / APP 应用层                                      |
|  boot.c 启动决策   updater.c 升级状态机   main.c 主循环        |
+--------------------------------------------------------------+
|  YMODEM 协议层 (平台无关, 可移植)                              |
|  ymodem.c 接收状态机   crc16.c 校验                           |
+--------------------------------------------------------------+
|  驱动层                                                       |
|  usart (DMA 环形 RX + TC 中断 TX)  flash  crc32(硬件)         |
+--------------------------------------------------------------+
|  模块层                                                       |
|  board (引脚契约)  led  key  systick  bootapi (BL<->APP 契约)  |
+--------------------------------------------------------------+
|  StdPeriph 库 + CMSIS                                         |
+--------------------------------------------------------------+
```

**依赖规则**: 只能上层依赖下层。协议层不包含任何 MCU 头文件, 通过回调注入收发, 因此可以在 PC 上做单元测试。

## 2. 数据流

```
Tera Term ──UART──> DMA2_Stream2 环形缓冲 ──轮询读取──> ymodem_feed()
                                                            │
                              ┌─────────────────────────────┤
                              ▼                             ▼
                      on_header (文件名/大小)        on_data (1024B 数据块)
                              │                             │
                      校验大小 + 擦除 Flash              Flash_Write (回读验证)
                              │                             │
                              └──────────> 完成 ──> CRC32 全量校验
                                                            │
                                                    保存元数据 -> 跳转 APP
```

## 3. 启动决策状态机

```
                    +----------------+
                    |  复位          |
                    +-------+--------+
                            |
                 +----------v----------+
                 | 备份寄存器魔数检查    |----- APP_REQ ---+
                 +----------+----------+                 |
                            |                             |
                 +----------v----------+                 |
                 | 按键保持检测 (50ms)  |----- KEY -------+
                 +----------+----------+                 |
                            |                             |
                 +----------v----------+                 |
                 | APP 有效性检查       |                 |
                 | 元数据+MSP+向量      |                 |
                 +----------+----------+                 |
                    有效    |   无效                     |
                +-----------+----------+                 |
                | 5s YMODEM 窗口       |                 |
                +-----------+----------+                 |
                 超时       |  收到文件头                   |
                +-----------v----------+                 |
                | 跳转 APP             |                 |
                +----------------------+                 |
                                                         v
                                                +------------------+
                                                | 升级模式          |
                                                | 无限等待 YMODEM   |
                                                +------------------+
```

## 4. 升级状态机 (updater)

```
WAITING --(收到文件头, 擦除 Flash)--> RECEIVING --(传输完成)--> FINALIZE
   ^                                      |                      |
   |         (YMODEM 中止, 自动重启)-------|           CRC32 + 元数据保存
   |                                      |                      v
   +------------------ (失败) ------------+              SUCCESS -> 延时 1s -> 跳转 APP
   |
   +--(窗口模式超时)--> TIMEOUT -> 跳转 APP
```

## 5. 关键设计决策

| 决策 | 理由 |
|------|------|
| YMODEM 替代私有协议 | 免上位机, 终端软件原生支持, 生态成熟 |
| 协议层回调注入 | 平台无关, 可单元测试, 可移植到其他 MCU |
| DMA 环形 + 轮询读取 | 无 IDLE 中断分帧缺陷, 支持连续多包, 零拷贝 |
| TX DMA + TC 中断 | 发送不阻塞主循环 |
| 元数据三重校验 | 防止跳转到坏固件 |
| 备份寄存器 + 软复位 | APP 重入 Bootloader 的标准方案 |
| 扇区数组擦除 | 分区变更时只改配置, 无魔数循环 |
| 懒擦除 (首个数据包时) | 擦除耗时数秒, 若在文件头回调中执行会导致发送端等待 ACK 超时重发; 延后到首包处理则重发包会被当作重复包正常恢复 |
| 末包填充截断写入 | YMODEM 末包按 1024 对齐填充, 写入量以文件头大小为准 |
| CAN 仅包间隙检测 | 数据字节可能等于 0x18, 不能在包内误判 |
