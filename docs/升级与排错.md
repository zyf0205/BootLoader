# 升级与排错

## 串口升级

连接 USB 转串口：

| 开发板 | USB 转串口 |
|---|---|
| PA9 / USART1 TX | RX |
| PA10 / USART1 RX | TX |
| GND | GND |

串口设置为 `115200-8-N-1`，关闭硬件流控。进入升级模式有三种方式：

1. 按住 PC13 后上电或复位，保持约 100 ms；
2. APP 运行中长按 USER 键（PC13）约 1.5 s，LED 快闪提示后复位
   进入（演示 APP 已内置，业务固件可调用 `Boot_RequestBootloader()`）；
3. APP 无效时自动进入恢复模式，无需按键。

等待终端看到 Bootloader 日志和周期字符 `C`，使用串口工具的 `Ymodem` 模式发送 EIDE 生成的 `App.bin`。标准 YMODEM 发送器可能自动使用 1 KB STX 数据包，Bootloader 可以正常接收。

不要使用普通“发送文件”，也不要发送 `.hex`。APP 必须链接到 `0x08004000`，直接使用仓库 `app` 目标生成的 BIN。

典型成功输出：

```text
File   : App.bin
Size   : ... bytes
Invalidating old metadata...OK
Erasing APP region...OK

Receiving done.
Calculating CRC32...done (...)
Saving metadata...OK

Update success! Rebooting to APP in 1 s...
```

## LED 状态

| 状态 | LED 表现 |
|---|---|
| Bootloader 等待传输 | 每 500 ms 翻转，完整周期约 1 秒 |
| Bootloader 接收/升级 | 每 100 ms 翻转，完整周期约 200 ms |
| 升级成功等待跳转 | 常亮 |
| APP 正常运行 | 快速心跳闪烁（50 ms 翻转） |
| APP 长按升级提示 | 按住期间转为 100 ms 快闪，1.5 s 后复位 |

## 常见问题

### 启动日志乱码

确认串口为 115200-8-N-1，并确认开发板实际晶振为 12 MHz。两个工程必须同时使用 `HSE_VALUE=12000000`、`CLOCK_USE_HSE=1` 和 `PLL_M=12`。只修改 `HSE_VALUE` 而未启用 HSE 不等于使用外部晶振。

### 一直显示 C

这是 Bootloader 正在邀请 YMODEM 发送端，不是普通文本输出。请选择 YMODEM 协议发送 BIN。正常启动且 APP 有效时会立即跳转；只有按键启动、APP 软件请求或 APP 无效时才会无限等待。

### 出现 Retry at block

少量重传表示发送端未及时收到 ACK，YMODEM 会自动恢复。接收端支持重复数据包去重，也支持最终空文件头 ACK 丢失后的重传。如果持续重试：

- 检查 TX/RX 是否交叉连接以及是否共地。
- 关闭硬件流控和串口工具的普通文本发送功能。
- 降低 USB 转串口链路干扰，避免同时有其他程序占用串口。
- 重新复位后开始一个新会话，不要在传输中切换包大小选项。

### 发送完成但没有 Update success

确认发送端完成了最终空文件头握手。新版状态机在 `DONE` 状态仍会 ACK 重发的结束空包。若仍失败，记录串口原始十六进制数据，重点检查末尾是否存在第二次 EOT、接收端 `ACK + C` 和序号 0 的空 SOH 包。

### 升级成功后再次看到 Bootloader

Bootloader 每次复位都会先运行，但 APP 完整有效且 PC13 未按下时应立即跳转。若持续停留在 Bootloader，查看日志是 `Update key held`、`Update requested by APP` 还是 `APP is missing or invalid`；后者表示元数据、向量表或 CRC32 校验失败，需要重新发送最新 `App.bin`。

### 提示 downgrade rejected

防降级保护生效：当前 APP 完好且元数据有版本号时，文件名版本低于
已装版本的固件会被拒绝（如已装 `v1.2`，发送 `v1.0`）。需要回退时，
将 BIN 文件名中的版本号改为不小于已装版本，或擦除 APP 进入 recovery
模式（recovery 态不做版本限制）。文件名不含 `vX.Y` 时不做版本检查。

### APP 与 Bootloader LED 看起来相同

当前设计中 Bootloader 等待模式完整周期约 1 秒，APP 完整周期约 500 ms。若仍相同，确认 YMODEM 发送的是最新 `app/build/app/App.bin`，并确认升级后出现 `Update success`。

## 构建排错

EIDE 构建异常时先检查工具链是否选择 AC5、microlib 是否启用、目标链接地址是否正确。Agent/CI 风格验证运行：

```bash
bash tools/build_check.sh
make -C tests/ymodem test
make -C tests/boot_policy test
```

Windows ARMCC 从 WSL 启动时必须使用仓库工作目录和相对源码参数；不要把 `/mnt/...` 绝对路径直接传给 Windows 编译器。
